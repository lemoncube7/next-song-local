# 다음 곡 · 로컬 시청 기록으로 노래방 선곡

YouTube와 YouTube Music의 시청 기록에서 익숙한 곡을 찾고 TJ·금영 번호를 연결하는 로컬 앱입니다.
시청 기록은 자기 PC의 SQLite에만 저장합니다. 친구끼리는 **확정된 분류 정보만 비공개 GitHub 저장소**로 공유합니다.

## 친구용 Windows 설치

v0.1.8의 분류된 곡 탭에서는 내 기록에 없는 공유 곡과 조사된 원곡도 검색할 수 있습니다. 전체·내 분류·공유 분류·내 기록 유무로 필터링하고, 별칭·노래방 번호·연결 영상을 확인합니다. 목록을 열어도 시청 기록이나 추천에는 곡이 추가되지 않습니다.

v0.1.5부터 데이터 가져오기 → 앱 업데이트에서 새 버전을 확인하고 설치할 수 있습니다. 기존 data 폴더와 계정 인증은 유지합니다. v0.1.4 이하는 한 번 ZIP으로 프로그램 파일을 교체하세요.

v0.1.7은 공유 정보를 곡과 영상 연결로 나눕니다. 원곡 링크, 정확한 제목·아티스트 별칭, 확인된 음악 DB ID를 재사용해 서로 다른 영상도 연결합니다. 영상의 원곡·커버·자막·리믹스 구분과 명시된 가창자는 곡의 원작자와 별도로 보관합니다. 기존 공유 파일도 읽고 제공하며, 새 문서가 완비되면 그 문서를 최신 기준으로 사용합니다. 연결 철회·정정은 다음 동기화에서 반영하고 직접 결정은 보호합니다.

저장된 분류·곡 번호·곡 별칭이 바뀌면 약 8초 모아서 동기화를 예약하며, 실행 중에는 5분마다 변경분을 확인합니다. 같은 파일은 다시 업로드하지 않습니다. 데이터 가져오기에서 실제 시청 영상 연결 수·추가·수정·철회·연결 근거와 충돌을 확인하고, 공유 연결 취소·다시 허용을 선택할 수 있습니다. 시청 시각·횟수·기록 원본·계정 인증 정보는 공유하지 않습니다. 기여한 영상 ID와 곡 정보는 모임 구성원이 볼 수 있습니다.

1. [최신 Windows 실행 패키지](https://github.com/lemoncube7/next-song-local/releases/latest)에서 `NextSong-Windows-x64.zip`을 받습니다.
2. 압축을 모두 풀고 `NextSong.exe`를 실행합니다. Python을 따로 설치하지 않아도 됩니다.
3. 브라우저에서 `http://127.0.0.1:8765/`가 열립니다. 실행 창을 닫으면 로컬 서버도 종료됩니다.
4. **데이터 가져오기 → 친구와 확정 곡 정보 공유 → GitHub 계정 연결**을 누릅니다.
5. 앱에 표시된 일회용 코드를 GitHub 인증 페이지에 입력하고 **자신의 계정으로** 승인합니다.
6. 공유 저장소 초대를 수락한 뒤 **분류 공유 켜기 → 공유 설정 저장 → 지금 받아오고 내 분류 올리기**를 누릅니다.
7. 본인의 Google Takeout 시청 기록 ZIP·JSON·HTML을 가져옵니다. 공유된 영상 ID는 조사 없이 먼저 연결됩니다.
8. **곡 확인하기 → 남은 영상 전체 자동 처리**를 실행하면 새로운 곡을 찾아 저장합니다. 공유를 켜 두면 30분마다 결과를 주고받습니다.

모임 관리자가 알려준 비공개 저장소 주소(owner/name)를 입력하세요. 초대된 사람만 접근합니다.
[초대 알림 확인](https://github.com/notifications)
다른 그룹은 자기 비공개 저장소를 만들고 README 등 최초 커밋을 하나 넣은 뒤 저장소 주소를 변경할 수 있습니다.

## 시청 기록 준비

[Google Takeout](https://takeout.google.com/)에서 모두 선택 해제 → YouTube 및 YouTube Music → 포함 데이터에서 기록을 선택합니다.
시청 기록 형식은 JSON 권장입니다. HTML도 지원합니다. ZIP이 여러 개면 필요한 기록이 든 파일을 가져오세요.
API 키는 공개 영상 정보 조회의 선택 기능이며 YouTube 계정 로그인이나 시청 기록 자동 다운로드가 아닙니다.
기록 파일·키를 친구에게 보내지 마세요. ZIP/JSON/HTML은 로컬 브라우저에서 로컬 서버로만 가져옵니다.

## 공유되는 항목 / 공유되지 않는 항목

공유: 영상 ID, 확정 곡명·가수, 검증된 제목 별칭, 연결된 TJ·금영 번호, 근거 종류.
공유하지 않음: 시청 기록 원본, 시청 시각·횟수, 영상 설명, 계정 프로필, API 키, 인증 토큰.
영상 ID 목록 역시 취향을 드러낼 수 있으므로 공유 저장소는 반드시 비공개입니다. 공개 저장소에는 업로드하지 않습니다.
직접 확인한 정보와 근거가 확인된 자동 분류·음원 메타데이터만 공유합니다. 추정 후보는 제외합니다.
자동 분류에는 오류가 있을 수 있습니다. 잘못 연결된 곡은 로컬에서 수정하세요.

각 앱은 무작위 클라이언트 ID의 폴더 아래 16개 작은 JSON 파일만 수정합니다.
서로의 파일을 덮어쓰지 않고, 같은 영상의 곡 정보가 다르면 충돌로 보관합니다.
직접 수정·제외한 결정은 공유 정보로 덮어쓰지 않습니다. 다운로드한 곡은 본인의 시청 기록에 등장한 경우만 추천합니다.
받은 정보를 자기 신규 분류인 것처럼 다시 업로드하지 않습니다. 서버컴이나 유료 호스팅은 필요 없습니다.
인터넷이 끊겨도 로컬 기능은 동작하며 다음 동기화 때 다시 시도합니다.

## 노래방 수록곡 역방향 탐색

데이터 가져오기에서 **전체 TJ·금영 목록 받기** → **수록곡으로 전체 기록 탐색**을 실행합니다.
Manana 비공식 전체 제공 목록을 받아 제목 색인으로 로컬 영상과 대조합니다.
곡명과 가수·원곡 근거가 함께 맞는 경우만 연결하며, 수록 예정 번호는 구분합니다.
업체 공식 최신 목록이나 모든 기기 지원을 보증하지 않습니다.

## 개발 / 소스 실행

Python 3.10 이상, 앱 실행에는 외부 Python 패키지가 필요 없습니다.
Windows는 `Start.cmd`, 다른 OS는 `python server.py --open`을 실행합니다.
소스 버전의 GitHub 연결에는 [GitHub CLI](https://cli.github.com/)가 필요합니다.
Windows 실행 패키지에는 공식 GitHub CLI와 라이선스가 포함됩니다.

```sh
python -m unittest discover -s tests
python -m pip install "pyinstaller>=6,<7"
python -m PyInstaller --noconfirm --clean --onedir --name NextSong --add-data "static:static" desktop.py
```

런타임 DB·기록·키는 `data/`에 저장되며 Git에서 제외됩니다. 새 버전으로 옮길 때 자신의 data 폴더를 보존하세요.
정리 내용 백업은 곡 수정·별칭·평가 등을 백업하지만 시청 기록 자체를 포함하지 않습니다.
앱 코드는 공개 저장소, 실제 분류 파일은 별도의 비공개 저장소입니다.

## Spotify 기록 가져오기 (v0.1.9)

데이터 가져오기에서 확장 스트리밍 기록 또는 일반 StreamingHistory JSON을 선택합니다. 여러 파일은 하나씩 가져옵니다. Spotify ZIP은 먼저 압축을 풀어 주세요. Premium이나 API 연결이 필요 없습니다. 곡명·아티스트·재생 시각을 로컬에 저장하며 계정 정보·IP는 읽어 저장하지 않습니다. 음악 정보가 없는 항목과 재생 시간 0인 항목은 제외합니다. 동일한 곡명·아티스트·시각의 중복 기록은 추가하지 않습니다. Spotify 항목은 현재 친구 공유에서 제외됩니다. 계정 연결·자동 API 동기화는 지원하지 않습니다.

### 재생 출처와 상세 정보 (v0.1.10)

Spotify의 원본 곡 URI·앨범과 재생별 시간·건너뛰기 여부를 로컬 DB에 보존합니다. 곡 상세에 출처별 기록과 Spotify 재생 시간을 표시합니다. 같은 곡명·아티스트로 묶여도 서로 다른 URI와 앨범은 음원별로 남습니다. v0.1.9에서 이미 가져온 Spotify 기록은 원본 JSON을 다시 가져오면 중복을 추가하지 않고 상세 정보를 보강합니다. 파일에 없는 필드는 추정해서 채우지 않습니다.

YouTube Music 출처는 명시적인 활동 머리말·products 또는 music.youtube.com 주소로 보존합니다. YouTube Music 라이브러리나 음원 크레딧의 곡명·아티스트가 있으면 바로 곡으로 확정합니다. 서비스에는 팟캐스트 등도 있으므로 출처만 있는 항목은 곡 정보 확인 대상으로 둡니다. 기존 기록의 출처가 없다면 원본 Takeout을 다시 가져오세요. 일반 YouTube 표기로 다시 가져와도 이미 확인된 YouTube Music 출처를 지우지 않습니다.


### 친구 · 함께 부를 곡 (v0.1.11)

- 친구 탭에서 GitHub 사용자명을 등록합니다. 상대도 내 사용자명을 등록하고 양쪽이 동기화하면 친구로 표시됩니다.
- 두 계정은 같은 비공개 분류 공유 저장소에 접근할 수 있어야 합니다. 친구 등록은 GitHub 저장소 초대를 대신하지 않습니다.
- 곡 목록 공유는 기본으로 꺼져 있습니다. 켜면 내 기록 속 곡명·아티스트·별칭·노래방 번호만 별도 목록으로 공유합니다. 시청 시각·횟수·원본 기록·영상 ID·API 키는 이 목록에 포함하지 않습니다.
- 친구의 공유 곡 목록을 검색하고, 곡명·가수·별칭 또는 노래방 번호가 일치하는 ‘함께 부를 곡’을 확인해 내 부를 목록에 담을 수 있습니다. 친구 목록을 보는 것만으로 내 시청 기록에 추가하지 않습니다.
- 비공개 저장소 참여자는 공유 파일을 읽을 수 있습니다. 상호 친구 등록은 앱의 표시 규칙이며 친구별 접근 제어가 아닙니다. 공유 해제 후 다음 동기화에서 현재 목록은 비워지지만 GitHub 과거 커밋에는 남을 수 있습니다.
- 같은 계정의 여러 PC 중 한 곳이 공유를 해제하면 비공개 설정을 우선합니다.

로컬 모델의 후보 선택은 보조 제안이며 자동 저장하지 않습니다. 모델 런타임·가중치는 Windows 패키지에 포함하지 않습니다. Gemini 대량 평가 코드는 소스에서만 시험 중이며 일반 앱 실행만으로 Gemini에 기록을 보내지 않습니다. API 키와 사용자별 평가 데이터는 배포하지 않습니다.

### Android PWA · 개인 기기 동기화 (v0.1.13)

공개 앱: https://next-song-mobile.lemoncube07.chatgpt.site/
Android Chrome에서 열고 메뉴 → 홈 화면에 추가 → 설치하세요.

PC 앱의 데이터 가져오기 → 모바일용 데이터 내보내기에서 개인 JSON을 저장하고 휴대폰의 가져오기에서 선택합니다. 추천·검색·노래방 번호·부를 목록·평가·팔로우는 기기 안에 저장되어 PC가 꺼져 있어도 사용할 수 있습니다. 휴대폰의 변경 파일을 PC로 가져오면 중복 없이 반영합니다.

선택 사항: PC에서 암호화 개인 동기화를 켜고 12자 이상 암호를 설정합니다. 휴대폰에서는 같은 비공개 저장소·개인 동기화 ID·암호와 해당 저장소 Contents 읽기·쓰기 GitHub 토큰을 입력합니다. 앱을 열고 잠금을 푼 동안 1분마다 교환하며, 완전히 종료하면 암호와 토큰을 다시 입력합니다. 최초 암호의 변경은 현재 지원하지 않습니다.

개인 추천용 시청 횟수·마지막 기록 날짜는 개인 파일에 포함됩니다. 친구용 공유 목록과 다르므로 내보낸 개인 파일을 친구에게 보내지 마세요. 자동 동기화 파일은 AES-256-GCM으로 암호화하고 PC 암호는 Windows DPAPI로 보호합니다. 원본 기록·영상 설명·YouTube/Gemini 키는 포함하지 않습니다. 브라우저 저장소 삭제 시 데이터가 지워질 수 있어 기기 백업을 권장합니다. 친구 정보는 마지막 PC 동기화 시점의 목록입니다.

소스 실행에는 Python 패키지 `cryptography>=46`이 필요합니다. Windows 실행본에는 포함됩니다.

### 공식 노래방 수록 확인·갱신 (v0.1.14)

데이터 가져오기 → 공식 노래방 수록 확인·갱신에서 켭니다. TJ·금영(KYSing)·DAM·JOYSOUND의 공개 공식 검색에 곡명·번호만 보내고, 시청 기록 원본·시각·횟수·계정 정보·키는 보내지 않습니다. 최초 조회 버튼을 누르기 전 자동 외부 조회는 꺼져 있습니다.

공식 결과의 곡명·가수·번호가 일치하고 7일 이내에 확인한 자동 번호만 ✓로 표시합니다. 공식 확인 전 번호는 후보로 보존하고 직접 입력 번호는 별도 표시합니다. 미래 수록은 현재 수록으로 확정하지 않습니다. DAM 번호 상세 조회 결과에는 기종별 수록일도 함께 표시합니다. 공식 검색 수록 확인은 매장 기기의 업데이트 완료를 보장하지 않습니다.

PC 실행 중 요청을 최소 1.2초 간격으로 보내고 자동 작업은 100건씩 나누어 진행합니다. 성공 결과는 7일, 결과 없음은 1일, 오류는 6시간 뒤 재조회합니다. 403·429이면 6시간 쉬고, 중지 버튼을 누르면 수동 재개 전 자동 작업을 멈춥니다. 공식 조회 오류가 기존 정보를 삭제하지 않으며 오래된 증거는 재확인 필요로 표시됩니다.

역탐색용 Manana 보조 목록도 7일 뒤 갱신하며, 보조 목록 새로 받기는 기존 파일 캐시를 건너뜁니다. 보조 목록과 공유 저장소에서 받은 정보 자체를 공식 확인 증거로 취급하지 않습니다. 폰은 확인 날짜를 표시하고 7일 만료 시 재확인 필요로 표시합니다. 새 번호를 받으려면 PC와 개인 동기화하거나 최신 모바일 파일을 가져와야 합니다.

### 친구 탭·번호 묶음·추천 변화 (v0.1.15 / 모바일 1.2.0)

같은 브랜드의 노래방 번호가 같으면 원본 분류를 삭제하지 않고 한 곡으로 묶어 표시합니다. 다른 표기는 별칭으로 보존하고 기록·평가·목록은 묶음에 반영합니다. 브랜드가 다르면 숫자만 같아도 묶지 않으며 직접 '다른 곡'으로 지정한 쌍은 유지합니다.

추천 카드에는 번호 대신 '번호 보기' 버튼이 있습니다. 버튼을 눌러 번호를 확인한 기록을 개인 추천 신호로 사용합니다. 실제로 노래를 불렀다는 확정 기록이 아닙니다. 같은 곡은 30분 내 반복 확인해도 한 번만 반영하며 가중치는 완만하게 증가하고 최대 15점으로 제한합니다. 이 기록은 친구용 공유 목록에 포함하지 않고 모바일 변경 파일/암호화 개인 동기화로 본인 PC에만 반영합니다. 모바일 변경 반영에는 PC v0.1.15 이상이 필요합니다.

기본 추천순에는 기존 취향 점수에 제한된 무작위 변화를 더합니다. 같은 추천을 보는 동안 버튼을 누를 때마다 재추첨하지 않으며 '다른 추천 보기', 재실행, 다른 탭에서 추천 탭 재진입 시 새로 섞습니다. 빈도순·최근순은 해당 정렬을 유지합니다.

친구 탭은 친구·받은 요청·상대 등록 대기를 구분하고 공유 설정은 접어서 표시합니다. 모바일에서 받은 요청을 수락할 수 있고, 친구별 공통 곡·공유 곡 수와 PC 동기화 필요 상태를 보여줍니다. 현재는 기존 PC/GitHub 동기화 구조를 유지하며 폰끼리 직접 통신하는 별도 서버는 추가하지 않았습니다.
